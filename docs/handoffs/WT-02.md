## Source limitations

- Verified cue durations come from `src/contracts/motion-tokens.json`. The runtime does not import `src/components/imessage`.
- Invisible ink stays on the message (`effect`, `revealed`). Duration 0 does not become a cue and does not divide.
- Send/receive cues use `messageMotion.send.duration` (690), `receive.duration` (300), or `reduced.duration` (200) when `reducedMotion` is set. Reduced motion is a demo flag, not `matchMedia`.
- iOS screen cues use `iosScreenTransition` and the pin's `screenTransitionKind` rules. macOS conversation cues use `macTransitions.conversation.duration` (140) and `selection.text` (110).
- Menu entrance uses `macTransitions.menu.open` (110). Thread, long-press, effects picker, plus menu, image viewer, and context-menu dismissal durations are the pin's own literals held in `pendingCueDurations` until the change request adds them to the token file. Thread exit is 200 ms from `replyThreadMotion.exit`. Context-menu dismissal is 120 ms from `context-menu.tsx`.
- Reply snapshots are the text stored on the reply event. Later edits do not rewrite them. `replyCount` is recomputed from messages that are still present.
- Typing and draft change only when an event says so.
- A second message event with an id that already exists is ignored.
- `beforeState` is the fold strictly before the newest still-active cached transition (screen navigation, overlay exit, macOS conversation switch). The cue keeps its own origin when several overlap. Progress `1` drops the cue; the logical scene is already the end state.
