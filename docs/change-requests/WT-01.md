# WT-01 contract requests

The frozen `ValidationIssue`, `DemoMessage`, and `CompiledDemo` types cannot carry the diagnostics, quote snapshots, or digests this lane was asked to emit. WT-01 did not edit `src/contracts/**`. Codes are prefixes on `ValidationIssue.message` until the signature below exists.

## 1. Diagnostic code and step id

Proposed change in `src/contracts/index.ts`:

```ts
export type ValidationIssue = {
  path: string;
  message: string;
  code:
    | "UNSUPPORTED_COMPONENT"
    | "CATALOGUE_ONLY"
    | "UNKNOWN_FIELD"
    | "MISSING_FIELD"
    | "INVALID_TYPE"
    | "INVALID_VALUE"
    | "INVALID_TIMESTAMP"
    | "DUPLICATE_ID"
    | "INVALID_REFERENCE"
    | "OVERLAPPING_ARRIVAL"
    | "INVALID_ANIMATION"
    | "INVALID_ASSET"
    | "PLATFORM_MISMATCH"
    | "CONTRACT_GAP";
  stepId?: string;
};
```

Failing use case: `{ "steps": [{ "id": "s0", "message": { "kind": "poll" } }] }` fails with pointer `/steps/0/message/kind` and code `UNSUPPORTED_COMPONENT`. Callers can only see that code by parsing `message`. `stepId` `s0` has nowhere to live but inside the string.

## 2. Reply, reaction, edit, removal, and explicit timestamps

Proposed additions on `DemoMessage`, matching the pinned `Message` fields the schema omitted:

```ts
replyTo?: { id: string; text: string; direction: Direction; service?: Service; sender?: string };
reactions?: Array<{ type: string; byMe?: boolean; emoji?: string }>;
edited?: boolean;
readAt?: number;
sentAt?: number;
```

`replyCount` stays off the authored message. The runtime recomputes it.

Failing use case, which `validateDemo` currently rejects with `CONTRACT_GAP` at `/messages/1/replyTo` instead of compiling the quote:

```json
{
  "id": "thread",
  "title": "Reply",
  "platform": "ios",
  "theme": "light",
  "contact": { "name": "Alex" },
  "nowMs": 1000,
  "draft": "",
  "typing": false,
  "screen": "conversation",
  "messages": [
    { "id": "in-1", "text": "Are you close?", "direction": "incoming", "atMs": 0 },
    {
      "id": "out-1",
      "text": "Yes",
      "direction": "outgoing",
      "atMs": 1000,
      "replyTo": { "id": "in-1", "text": "Are you close?", "direction": "incoming" }
    }
  ]
}
```

The same gap blocks a valid outgoing `edited: true`, a `removed: true` message with no live replies, a tapback array, and explicit `readAt` / `sentAt`. Invalid cases already fail with `INVALID_REFERENCE` or `INVALID_VALUE`: a forward reply, removal while a live reply remains, an incoming edit, and a reaction whose target id is not an earlier live message.

`MessageLink.image` is also on the pin and absent from `demoMessageSchema`. An authored preview image is `UNKNOWN_FIELD` at `/messages/N/link/image`.

## 3. Compiled digests, checkpoints, and token references

Proposed additions on `CompiledDemo`:

```ts
sourceDigest: string;
scenarioDigest: string;
checkpoints: Array<{ id: string; atMs: number }>;
tokens: {
  sendDurationMs: number;
  receiveDurationMs: number;
  bubbleEffectDuration: Record<"slam" | "loud" | "gentle" | "invisible-ink", number>;
};
```

Failing use case: two compiles of the foundation flow are deep-equal, but a caller cannot read a source digest or the token reference from `CompiledDemo`. Adding those fields in the compiler is a type error against the freeze. Checkpoints on the input are `UNKNOWN_FIELD` at `/checkpoints`.

## 4. Foundation boundary test

`tests/contracts/boundaries.test.ts` still requires `validateDemo` and `compileDemo` to throw `NOT_IMPLEMENTED`. That test is outside this lane. After this lane lands, the production-boundary test should keep asserting `NOT_IMPLEMENTED` for `stateAt`, `frameAt`, and `createPlayer` only.
