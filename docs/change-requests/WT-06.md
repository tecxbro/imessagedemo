# WT-06 contract requests

Contracts, root Playwright config, and other lanes were not edited. These are the changes this corpus cannot express. Each one names the failing input.

## 1. Reject unknown keys

`demoFlowSchema` and `demoMessageSchema` strip unknown keys. `validateDemoDouble` then returns `ok: true` for `tests/negative/reactions.json`, `group-chat.json`, `invalid-reply-removal.json`, `edit-removal-final.json`, `link-unfurl.json`, and `attachment-download.json`. The message data is gone, so a renderer would show an ordinary bubble.

`validateDemo` should fail those objects. Diagnostics already computed by `tests/fixtures/diagnose-demo.ts`:

- `messages.0.reactions` — `Unrecognized key: "reactions"`
- `group` — `Unrecognized key: "group"`
- `messages.0.sender` — `Unrecognized key: "sender"`
- `messages.2.replyTo.id` — `reply target is missing or removed`
- `messages.0.link.image` — `link images are not unfurled`
- `messages.0.attachments.0.href` — `attachment href is not allowed`

Proposed addition, once the fields below exist: keep `.strict()` on the flow, the message, `link`, attachment items, image items, and `audio`. Semantic checks in `diagnoseDemo` stay after the schema parse.

## 2. Fields the pin already renders

`Message` in `src/components/imessage/message-list.tsx` already has `sender`, `reactions`, `replyTo`, `edited`, and `effect`. `DemoMessage` has `effect` only.

```ts
reactions: z.array(z.object({
  type: z.enum(["love", "like", "dislike", "laugh", "emphasize", "question"]),
  byMe: z.boolean().optional(),
})).optional(),
replyTo: z.object({ id: z.string().min(1) }).optional(),
edited: z.boolean().optional(),
removedAtMs: z.number().int().optional(),
sender: z.string().min(1).optional(),
```

`edited: true` is the settled `EditedLabel`. `removedAtMs` means the message is absent. Neither field drives `EditableBubble` or `UndoSendPoof`.

Failing input: `tests/negative/edit-removal-final.json` and `tests/negative/invalid-reply-removal.json`. A reply whose target has `removed: true` or `removedAtMs` must keep the path `messages.2.replyTo.id`.

## 3. Playback time and sent time

`DemoMessage.atMs` is an absolute clock in every authored scenario (`nowMs` is `2026-09-21T16:41:00.000Z`). Date headers need that clock. A short capture timeline needs another one. `compileDemoDouble` discards `message.atMs` and schedules `index * 1000`. The unit test "shows the frozen double scheduling messages by index instead of atMs" locks that gap.

```ts
atMs: z.number().int().nonnegative(),
sentAtMs: z.number().int(),
```

`atMs` is playback. `sentAtMs` is the date separator clock. Failing use case: `scenarios/long-thread-ios-light.json` needs three date headers (`buildRows` already returns them from the absolute stamps) without a 25-hour capture.

Typing and draft are single fields, so `scenarios/typing-status-*` is typing for the whole flow. Checkpoints are outside the schema, in `tests/fixtures/checkpoints.json` (152 ids).

Every macOS scenario is also forced to carry `screen: "conversation"` because the field is required. Prefer a discriminated platform object so macOS flows omit `screen`.
