# WT-02 contract request

The runtime lane implements the deterministic fold and playback clock without editing `src/contracts/**`. Frozen `CompiledDemo` can express message arrival, typing, and draft changes. It cannot express the rest of the scene the renderers have to seek. `motion-tokens.json` also omits the overlay exit durations the pin uses to keep a closing layer mounted.

`tests/runtime/contract-gap.test.ts` records the missing token symbols. The event-union use case below does not typecheck against the freeze, so it is not added to the suite.

## Failing use case

A compiled script needs to replace tapback `r1` on message `m2` at 900 ms and remove that same id at 1200 ms. The frozen event union cannot name that script:

```ts
import type { CompiledEvent } from "@/contracts";

const replace: CompiledEvent = {
  type: "reaction",
  atMs: 900,
  messageId: "m2",
  reactionId: "r1",
  reaction: { type: "love", byMe: true },
};
```

`tsc` reports that `"reaction"` is not assignable to `"message" | "typing" | "draft"`. The same hole blocks edits, removals, reveals, screen changes, conversation selection, scroll, window focus, overlays, and screen effects. Without `initialState`, a macOS switch also has no previous conversation to put in `beforeState`.

Invert the token assertion once the symbols land. Today this fails:

```ts
import motionTokens from "@/contracts/motion-tokens.json";

const symbols = motionTokens.tokens.map((token) => token.symbol);
expect(symbols).toContain("replyThreadMotion");
```

## Proposed `CompiledDemo` additions

Keep every current field. Treat `screen` as the screen at time 0. Add:

```ts
export type Reaction = { id: string; type: string; byMe?: boolean; emoji?: string };
export type ReplySnapshot = { id: string; text: string; direction: Direction; service?: Service; sender?: string };
export type SceneMessage = DemoMessage & {
  edited?: boolean;
  reactions?: readonly Reaction[];
  replyTo?: ReplySnapshot;
  revealed?: boolean;
};

export type OverlayState =
  | { kind: "closed" }
  | { kind: "thread"; rootId: string }
  | { kind: "long-press"; messageId: string }
  | { kind: "context-menu"; messageId: string; x: number; y: number }
  | { kind: "plus-menu" }
  | { kind: "effects-picker"; tab: "bubble" | "screen"; draft: string }
  | { kind: "image-viewer"; messageId: string; index: number };

export type CompiledEvent =
  | { type: "message"; atMs: number; sourceIndex?: number; conversationId?: string; message: SceneMessage }
  | { type: "typing"; atMs: number; sourceIndex?: number; conversationId?: string; typing: boolean }
  | { type: "draft"; atMs: number; sourceIndex?: number; conversationId?: string; value: string }
  | { type: "status"; atMs: number; sourceIndex?: number; messageId: string; status: MessageStatus }
  | { type: "reaction"; atMs: number; sourceIndex?: number; messageId: string; reactionId: string; reaction: { type: string; byMe?: boolean; emoji?: string } | null }
  | { type: "edit"; atMs: number; sourceIndex?: number; messageId: string; text: string }
  | { type: "remove"; atMs: number; sourceIndex?: number; messageId: string }
  | { type: "reveal"; atMs: number; sourceIndex?: number; messageId: string; revealed: boolean }
  | { type: "screen"; atMs: number; sourceIndex?: number; screen: IosScreenName }
  | { type: "select-conversation"; atMs: number; sourceIndex?: number; conversationId: string; contact?: DemoFlow["contact"] }
  | { type: "scroll"; atMs: number; sourceIndex?: number; conversationId?: string; offset: number }
  | { type: "window-active"; atMs: number; sourceIndex?: number; active: boolean }
  | { type: "overlay"; atMs: number; sourceIndex?: number; overlay: OverlayState }
  | { type: "screen-effect"; atMs: number; sourceIndex?: number; effect: ScreenEffectName; messageId?: string };

export type InitialState = {
  conversations?: readonly {
    id: string;
    contact?: DemoFlow["contact"];
    messages?: readonly SceneMessage[];
    draft?: string;
    typing?: boolean;
    scroll?: number;
  }[];
  selectedConversationId?: string;
  screen?: IosScreenName;
  windowActive?: boolean;
  overlay?: OverlayState;
};

export type CompiledDemo = {
  /* existing fields */
  events: CompiledEvent[];
  initialState?: InitialState;
  reducedMotion?: boolean;
};
```

`stateAt` should be typed as the logical scene (`LogicalState` in `src/runtime/types.ts`), not only `PlaybackState`. The object already includes `timeMs`, `playing`, and `durationMs`, so current `PlaybackState` readers keep working. `frameAt` should be typed as `VisualFrame` (`cues` and `beforeState` included).

```ts
export type LogicalClock = {
  now(): number;
  requestFrame(callback: (timestamp: number) => void): number;
  cancelFrame(handle: number): void;
};

export function createPlayer(compiled: CompiledDemo, options?: { clock?: LogicalClock }): PlayerController;
```

`PlayerController` is `Player` plus `reset(): number`, `seek` returning the revision, `revision()`, `getSnapshot()`, `subscribe()`, and `dispose()`. `seek` / `reset` already return a number at runtime.

## Proposed motion tokens

Add these literals to `src/contracts/motion-tokens.json`. They are copied from the pin; they are not measured by `scripts/extract-motion-tokens.mjs` today.

| Symbol | Value | Source literal |
| --- | --- | --- |
| `contextMenuDismiss` | `{ "duration": 120 }` | `context-menu.tsx` dismissal animation |
| `macPlusMenuMotion` | `{ "enter": 160, "exit": 120 }` | `macos-plus-menu.tsx` `macPlusMenuMetrics.motion` |
| `replyThreadMotion` | `{ "enter": 260, "exit": 200 }` | `message-reply.tsx` `replyThreadMotion` |
| `messageActionsTiming` | `{ "enter": 600, "exit": 220 }` | `message-actions.tsx` `messageActionsTiming.total` / `.exit` |
| `effectsPickerTiming` | `{ "enter": 260, "exit": 200 }` | `ios-effects-picker.tsx` `effectsPickerMetrics.timing` |
| `imageViewerTiming` | `{ "zoom": 300 }` | `image-viewer.tsx` `timing.zoom` |

Until those symbols exist, `src/runtime/tokens.ts` `pendingCueDurations` carries the same numbers. Context-menu entrance already uses verified `macTransitions.menu.open` (110). Message, screen, conversation, bubble, and fullscreen-effect cues already read `motion-tokens.json` only.
