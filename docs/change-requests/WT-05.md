Frozen files were not edited. These shared switches are required for WT-00 assembly.

## 1. `src/App.tsx` player host mount

**Why:** Root route wiring is outside WT-05 ownership. CLI preview/capture uses a player-owned Vite root at `src/player/host` so this lane can proceed. `npm run dev` still mounts only foundation shells.

**Proposed change** in `src/App.tsx`:

```tsx
import { PlayerHost } from "@/player";
import type { DemoRunManifest } from "@/player";

// After the foundation query-param branch, if window was booted with a run manifest:
// GET /__demo/manifest.json → <PlayerHost manifest={manifest} />
```

Exact signature already exported: `PlayerHost({ manifest: DemoRunManifest })`.

**Failing use case:** `npm run dev -- --host 127.0.0.1 --port 4173` then open `/?scenario=<id>` does not mount `DemoPlayer` until App.tsx reads the run manifest.

## 2. Renderer ready receipt on `RendererHandle`

**Why:** Capture must return the renderer’s exact receipt. Frozen `RendererHandle` is only `{ seek(timeMs): void; readonly element: HTMLElement | null }`. The player synthesizes a receipt from the frame element box plus the runtime frame digest.

**Proposed addition** in `src/contracts/index.ts`:

```ts
export type RendererReceipt = {
  timeMs: number;
  platform: DemoPlatform;
  theme: DemoTheme;
  width: number;
  height: number;
};

export type RendererHandle = {
  seek(timeMs: number): void;
  ready(revision: number): Promise<RendererReceipt>;
  readonly element: HTMLElement | null;
};
```

**Failing use case:** A renderer warm-up animation that does not change `element` still needs a revision-specific `ready(revision)` from WT-03/WT-04. The player currently waits for the element, fonts, and images, then hashes the runtime frame.

## 3. Playwright project for player/CLI capture

**Proposed project:**

```ts
{
  name: "player-capture",
  testMatch: /player\/.*\.spec\.ts/,
  use: { browserName: "chromium" },

```

**Failing use case:** `npm run test:e2e` never executes assembled player capture specs.
