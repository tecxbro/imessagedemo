# WT-03 contract requests

The iOS adapter implements these behaviors on the frozen `RendererProps` / `RendererHandle` types. The signatures below are not applied. Each one names a failing use case the current freeze cannot express.

## `RendererHandle.settle`

```ts
export type SettleReceipt = {
  revision: number;
  width: number;
  height: number;
  timeMs: number;
  theme: DemoTheme;
  digest: string;
};

export type RendererHandle = {
  seek(timeMs: number): void;
  readonly element: HTMLElement | null;
  readonly revision: number;
  settle(revision: number): Promise<SettleReceipt>;
};
```

Failing use case: a capture at playback 1200 ms must wait until the send ghost exists, fonts and images have loaded, the log has been pinned, and `--bubble-bottom` matches the laid-out bubbles. `seek` returns before that. Calling `settle(1)` after a later seek must reject instead of resolving the previous frame. The iOS handle object already has `revision` and `settle`; a `RendererHandle` ref hides them.

## `DemoMessage` transcript fields the pin already has

```ts
replyTo?: { id: string; text: string; direction: Direction; service?: Service; sender?: string };
replyCount?: number;
edited?: boolean;
readAtMs?: number;
reactions?: Array<{ type: string; byMe?: boolean; emoji?: string }>;
```

Failing use case: `capabilities.json` lists tapback, reply, and edited as supported, but `demoMessageSchema` has none of those fields. A direct `RenderFrame` cannot show a love tapback or a quoted reply, so the long-press measurement of a reply body is a catalogue scene that passes `Message` into `IosMessagesApp` rather than a timeline fixture.

## `RenderFrame` checkpoint fields

```ts
scrollTop?: number | "end";
longPress?: { id: string; progress?: number } | null;
thread?: { rootId: string; progress?: number } | null;
effectsPicker?: { tab?: "bubble" | "screen"; progress?: number; draft?: string } | null;
```

Failing use case: the frozen frame cannot name a scroll offset or an overlay. The adapter always pins the log to its end after layout, and overlays exist only as catalogue scenes. A checkpoint that must show the top of a long transcript, or a long-press at progress 0.4, cannot be compiled.
